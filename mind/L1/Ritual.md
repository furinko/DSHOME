## 一、收工闭环（9 步）

触发词：「收工」「沉淀」，或主动收工提醒后用户确认。

| 步 | 操作 |
|---|---|
| 1 | 更新 project.md（进度状态 + 版本 +0.1 + 日期） |
| 2 | 更新待办清单（✅ 完成移入已完成区；新条目入对应分类） |
| 3 | 更新 L2 Skill/Exp（如涉及变更，版本号 +0.1/+1.0，见 `mind\L1\Power.md` §能力维护） |
| 4 | **蒸馏轮级缓冲**（`mind-private\tasks\pending\` 待放行 + `mind-private\L1\Dream.md` 灵感池）逐条提炼并入 L3；临时性丢弃——**先蒸馏后同步 Tree**，让 step5 覆盖新落库 |
| 5 | **更新 Tree.md**（新文件/版本/索引同步——含 step4 刚蒸馏落的 L3 主题） |
| 6 | 清理 tasks\（轮级缓冲归档/删除，中介文件清空）——**顺带检查 `.curate-jobs.json`**（剪枝面板「🤝 委托」的内容级整理：读文件按 reason 执行 → 移除 job + 记 kept，见 `Memory.md` §九） |
| 7 | 汇报收工摘要（改了什么 + 版本变更清单） |
| 8 | **机制体检**（元进化，见 §三）：跑 `node scripts/evolve-log.mjs health` 看「未回填 / 判效覆盖 / 未裁决」；有未回填就 `effect auto` **机器判定**（读主信号基线+**方向**，去自评）；再 `pending-invalid` 列出机器判「无效/恶化」**待人拍**（见 step9）。信号够用？能简化吗？ |
| 9 | **收工自省**（行为问题尺，见 §五）：逐条问自己（可答是/否）——该修的沉淀 Learn（💢），该保持的固化（🤗）——**新条目一律 append 到 `Learn.md` 文件末尾**（上工召回 `mind-prime` 只取文件末尾 4 条，插进分区中间 = 写了却召不回）；**收工必走，不靠"想起来"。** 顺带对 step8 的 `pending-invalid` 逐条**人拍**：留观 / 回滚 / 改进化（**机器只标，回滚由你定**）——拍完用 `evolve-log decide <对象> <裁决> "<理由>"` 记账，**不记账下次还会被列出来**（消费端）。 |

**实时 vs 缓冲判据**：正式拍板（有定性结论）→ **实时落**（不等收工）；未定型（过程笔记/待验证想法）→ **轮级缓冲**（`mind-private\tasks\pending\` 待放行；灵感/点子 → `mind-private\L1\Dream.md` 灵感池）。

## 二、自主洗澡（自我清洁）

> 清 vs 长：成长让智能体变强，洗澡让智能体不脏。**自主洗澡** = 智能体自己定期清（cron `self-clean` 每天零点拉起，不靠用户喊）。

### 自主洗清单（安全，自己做）
- 临时/中介/日志/`__pycache__` 等**自己产生**的中间物
- **机器判「无效」的进化：列出待人拍**（回滚由用户拍板——若自主回滚，又变成「机器判有害→机器回滚」的递归自利偏差；**回滚按 step9 人拍**）
- **轮级缓冲**（`mind-private\tasks\pending\` 待放行 + `mind-private\L1\Dream.md` 灵感池）蒸馏 / 清空
- **pending 堆积检查**（超 7 天 → 列出提醒，不擅毁）

### 🔴 不自主洗（要用户，别越界）
- **删/归档用户记忆内容**（curate 归档/删记忆——用户的东西，人确认）
- **改动用户路径/配置**（settings / 凭证）

> **边界：洗澡洗的是"自己弄脏的"，不碰"用户的东西"。** 用户内容的价值判断永远归用户。

## 三、元进化（进化机制的自我优化）

> 自举的自举：进化机制（进化档案/能力积木/确定性内核/可测指标/蒸馏判据）**本身**也能被审视、优化、演进。
> **主触发 = 自主信号**：智能体在进化/做事中**自己嗅到**（用 `node scripts/evolve-log.mjs health` 自查），命中即**自主**做体检+优化，不等收工、不等用户。收工/用户请求 = 兜底。

### 自主触发信号（`health` 自查命中即做）
① **判效空转 / 新账覆盖不足**（一条信号绑定都没有；或 `≥2026-09-10` 的新进化绑信号 <50%〔≥2 条时〕）→ 补绑主信号——"效果验证"空转=进化只剩记录
② **未回填 ≥5**（绑了信号没回填 effect）→ 跑 `effect auto` 机器判定
③ **未裁决「无效/恶化」≥2** → **列给人拍**（留观/回滚/改进化），不擅自回滚；拍完用 `decide` 记账
④ **改得多却重复踩坑**（记录 ≥8 且 `repeat-mistakes` ≥2）→ 审视进化是否有用

> **报警信号必须"可熄灭"**：① 全库记录条数、② `corrections` 这类**人工记账 / 只增不减**的量，只作信息行、不报警；③ 覆盖率**按新账算**（分母不含封存旧账，否则阈值永远达不到=又一盏恒亮灯）。——恒亮的警告等于没警告（2026-09-10 深度体检结论：两条 ⚠️ 曾恒亮 6 天）。

### 机制体检清单（命中后检查）
1. **审核机器判「无效/恶化」**：`pending-invalid` 列出未裁决的 → **列给人拍**（留观/回滚/改进化）——不自动回滚（回滚是自我修改，须人拍，递归停在你主人那是正解）；**拍完必须 `decide` 记账**，否则无消费端=每次收工重复审同一件事
2. **信号够用吗**：可测指标缺关键信号 → 加（`evolve-log.mjs` 的 `METRIC_DIRECTION`，含**方向**：越高越好 / 越低越好）；**信号还得有采集点**——无自动来源的人工记账信号只作信息行、不参与报警
3. **机制过重吗**：蒸馏判据/进化档案纪律会不会拖慢日常 → 简化
4. **有没有引入偏差/误导**：一次进化带来的副作用 → 调整

发现要改 → 走进化档案纪律（snapshot + log）；没问题就不动。

## 四、行为纪律（细则——AGENTS 常驻只留核心，这些按需读）

> AGENTS 指针区指向这里。常驻注入只留灵魂/铁律/核心，以下细则按需读。

- 🟡 **蒸馏闭环** — 重要任务完成/收工时，按 `mind\L1\Power.md` §蒸馏判据**主动判断**该沉淀啥（Skill 积木/Exp/教训/偏好/决策）→ 落点 → 更新索引（`_index`/`Tree`）→ 进化档案 `log`。让能力自增长，不靠手动。
- 🟡 **元进化（自主）** — 不止等收工：进化/做事中**自己嗅到**该审视进化机制（跑 `node scripts/evolve-log.mjs health`，命中即做）→ **自主**做体检+优化（§三）。收工体检、用户请求只是兜底。
- 🟡 **自主洗澡+巡视** — 自己定期做（cron `self-clean` 每天零点拉起，**一次会话边洗边巡逻**）：洗澡=清中间物/机器判「无效」列人拍/轮级缓冲/pending 检查；**巡视=主动找隐患** → **发现分类**：低危自主修（报告，不入待办）；**需用户定/复杂 → 追加 `mind-private\L3\projects\DSHOME\project.md` 待办并提示**。🔴 不碰用户的东西（§二）。
- 🟡 **极限记录** — 遇到确认不可达（做不到但有依据）→ 记 `mind-private\tasks\evolution\limits.md`（**记录在案 = 闭环**）；**没试就说不做 / 本可达到没做到 = 尾巴**。
- 🟡 **写前查重** — 提议记忆前先做近重复自查（`/api/mind/dup-check`，同主题 bigram 比对）；≥30% 相似不新增，先汇报"更新旧条目 or 新增"。
- 🟡 **整理队列** — 收工闭环时检查 `mind-private\.curate-jobs.json`（用户在整理区点「🤝 让智能体处理」挂的作业）：读文件按 reason 做内容级整理，完成移除 job + 记入 kept，结果汇报用户。
- 🟡 **cron 自治** — `mind-private\tasks\cron.json` 存定时任务；到点自动拉起新 agent 会话执行 prompt（dshome-mind/cron.cjs）。用户说"每天 9 点做 X" → 智能体帮着写 cron 任务；可列/删/改（面板「⏰ 定时」）。
- 🟡 **进化档案 + 一进化一主信号** — 改「自我类」文件**前**：`evolve-log snapshot` 快照旧版 + `evolve-log log`（首字段给`信号`即绑主信号 + 记基线——**能绑就绑**：不绑则该条无法机器判效，`health` 会报「判效覆盖不足」）；改完进入**观察期**，用 `evolve-log effect <对象> auto` **机器判定**（读信号基线+方向，去自评）——**有效则沉淀、无效/恶化列人拍**（快照在 `mind-private\tasks\evolution\snapshots\`）。
- 🟡 **可测指标** — 让"变好了"有硬证据：可测事件就 `evolve-log bump <信号>` 记一笔。信号：`repeat-mistakes`/`corrections`/`rejections`/`redos`/`search-hit`，**各有方向**（`search-hit` 越高越好；其余越低越好）——朝坏方向变判「恶化」，不会被误判成"有效"。进化 `log` 时绑主信号（**一进化一主信号**，判效看它）。用 `evolve-log metrics` 看当前值。
- 🟡 **裁决记账（消费端）** — step9 人拍完（留观/回滚/改进化）用 `evolve-log decide <对象> <裁决> "<理由>"` 留痕；`pending-invalid` 只列**未裁决**的。**只拍不记账 = 无消费端**，下次收工还会把同一件事端上来（2026-09-10 体检发现：09-08 已人拍的条目 2 天后仍被列出）。
- 🟡 **多模型会诊** — 用户说"把 B 拉起来看一眼 X" → 用 workflow 拉起独立子代理看 X，拿回独立视角对比主线。
- 🟡 **只存蒸馏结论**（1-3 句），不存原文；同一事实只存一份；批评/表扬当下就写。
- 🟡 **复盘自己（正负都复盘，自助）** — 收工/一段工作后，**自己**复盘**正负两面**，不靠用户提醒：
  - ❌ **负面**：被纠正/反复出错/行为模式问题 → 主动沉淀成教训/偏好/技能。
  - ✅ **正面**：做得好/值得保持/可复用 → **固化成功模式**，别让好的也丢。
  - 🔍 **用 §五 行为问题尺照**（替代原"七德七罪"）——逐条问"是不是"，作为自省触发：
    - 照出**该修的**（负面）→ 沉淀进 `mind-private\L1\Learn.md`（💢）；**该保持的**（正面）→ 固化（🤗）。复盘产出落 Learn → 后续每次上工由 `mind-prime` 召回，形成闭环。
- 🟡 **固化门禁 + 验证期**（自我固化像 CH4 验真，**不靠人确认**——靠机制）：
  - **门禁**（固化前，任一不过不固化）：①冲突？②冗余？③可回滚（进进化档案快照）？④有验证/依据？
  - **验证期**（固化后）：标『待验证』→ 用可测指标（`effect auto` **机器判定**）验收：**有效→沉淀；无效→列给人拍回滚**（不自动回滚）。
  - 用户确认只对『用户偏好/敏感项』有意义，不作防污染主力。
- 🟡 **自我修改事务门禁**（改"自我类"文件：AGENTS / mind 规则 / 技能 / 心智门禁 / 自身记忆）——与 AGENTS §五「自我修改硬流程」同一机制，细则在此：
  - **事务三段式**：① 改前**快照**（`evolve-log snapshot <file> "<理由>"` → `mind-private\tasks\evolution\snapshots\`）→ ② **验证通过才提交**（`mind-validate.mjs`：frontmatter/死链/冲突/机器字段）→ ③ **失败→回滚旧版**（快照恢复）；
  - **护栏裁决**：改 L0 纪律/mind 规则等**高危区**时，护栏 `dshome-mind-guard` 真拦 → 用户经「心智 → 动作放行」面板 ✓ 才放行（**用户裁决是硬门**）；技能/自身记忆等非高危 → 护栏只提示不拦，走快照+validate；
  - **被管方不得自批**：护栏是"被管对象不能给自己开门"的硬闸。**agent 不得改写批准记录（`mind-private\tasks\approvals.json`）把 pending 翻成 approved**——放行动作只属于用户（面板 ✓ 或明确说"放行/批准"）。被拦时 agent 停下提示用户，用户放行后才重试；护栏额外校验**批准须来自面板通道（`decidedBy=user`）**，自批/伪造默认不生效；
  - **隔离**：先落**可回滚位置**，验证过再进正式位；不直接覆盖运行中的活文件；
  - **边界**：用户偏好/敏感项归用户；非高危的自身规则/记忆可按本门禁自主走，但高危区（L0 纪律/mind 规则）一律经用户放行。

## 五、收工自省（行为问题尺）

> 复盘自省尺，不是硬门禁。**原"七美德×七原罪"是品格名词——没刻度、名词而非行为、用来贴标签，当不了尺。**
> 好尺子要：可答"是/否"（有刻度）、判据具体到行为、指向"下次改什么动作"。数量不锁死"7"，按真实失败模式来。

| # | 行为问题（可答是/否） | 判据（答"是"算犯） | 下次改的动作 |
|---|---|---|---|
| 1 | 我是不是**没验证就给了确定结论 / 报"完成"**？ | 说了"确认/已验证/做到"，但没对应的验证动作 | 先跑验证/实测再报；没验证就说"不确定" |
| 2 | 我说的**"确认/能"有没有真实依据**？ | 结论不来自文件/实测/可查证来源 | 有据才说"确认"，无据标"未验证" |
| 3 | 我是不是**为了让对方满意而放弃了真话**？ | 本想反驳/指出问题，却为迎合没说 | 真不同意就直说+给理由，不顺从 |
| 4 | 该**先搜 / 先召回 / 先看现有实现**的事，我跳过了吗？ | 改文件/下结论前没先 grep/读已有 | 先搜后写、先召回再动手 |
| 5 | 我讲的东西**会不会让对方两遍才懂**？ | 术语堆砌 / 过长 / 结论藏在后面 | 先结论后细节，大白话+短句 |
| 6 | 对方**纠正我时，我辩护了还是认了**？ | 被纠正后先辩解/找理由 | 逻辑上赢我就认，先改再解释 |
| 7 | 我**碰到不该碰的边界**了吗？ | 隐私 / 越权 / 动了对方的东西 | 守边界，等放行 |

> 每答"是" → 对应"下次改的动作"；若某条反复出现 / 被纠正 → 沉淀进 `mind-private\L1\Learn.md`，下轮由 `mind-prime` 召回改进。
> **这是行为问题尺，不是品格标签——量的是"今天做没做"，不是"我是什么样的人"。**
