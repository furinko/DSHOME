## 一、规则

- 用户冒出点子（通勤怪点子/调研灵感/讨论火花）→ **当场落池**，不丢。
- 实际内容写在 `mind-private\L1\Dream.md`（隐私区；本文件为出厂模板）。
- 落池判据（什么样算灵感，与待办/建议区分）：**未经验证、还没想清楚要不要做、只是"觉得有意思/可能有用"的松散想法** → 灵感池；已经是明确下一步 → Project todo；对现有系统的改进 → suggestion；行为纠正/偏好 → Learn/user-rules。

## 二、条目格式

每条一行/一段：
```
[YYYY-MM-DD] 点子：<内容>
状态：挂起 | 已拉入 | 已作废
出处：<对话/文档/思考>
触发条件：<什么情况下值得做>
```

## 三、整理提醒

- **可执行条目 ≥3 条** → 主动提醒用户整理。⚠️ **判据＝"触发条件已到"的条目数，不是池子总条数**（2026-09-18 订正）：池里挂着 3 条但**触发都没到** ⇒ **不提醒**（复核留一行痕迹即可，见私池 §三 台账）。**为什么改**：原写「池中 ≥3 条」= **恒亮灯**——本机池里长期挂着 ≥3 条挂起项、触发条件又都没到，于是每轮收工/自治都要提醒一次（09-16 一天被提醒两次），而"恒亮的警告等于没警告"（`limits.md`）。整理动作本身不变：该蒸馏的蒸馏（→ L3/技能），该落待办的落待办（→ `mind-private\L3\projects\<当前项目>\project.md` 待办区，**不是已废止的顶层 `Project\`**），该丢弃的作废。
- 每次开新任务：扫一遍 Dream——适合当前工作的拉入执行线，不适合的继续挂。
- 开新任务扫池、整理提醒均在收工闭环执行（见 `mind\L1\Ritual.md` §一 **step4** 蒸馏轮级缓冲；step5 是同步 Tree）。
