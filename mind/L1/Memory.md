# Memory.md — L3 规则书

> 版本：1.5 | 2026-09-04 | union：凌晨 1.4（§二/§五 门禁对齐 §八 溯源信任 + 日期锚 + importance 写时五档/调整规则）⊕ 公司 §十（读时 4 维调取评价）；版本日期校正
> 加载：强制层（每次上工必读）
> 定位：L1 海马体——定义 L3 index/history 与 Project 的归档规则。L3 引用 Memory 来规定自己。

## 一、L3 三种类型边界

| 类型 | 定位 | 生命周期 | 修改规则 |
|---|---|---|---|
| **index** | 结晶知识（踩坑沉淀/设计/速查） | 持续积累 | 增量覆写，删除须用户确认 |
| **history** | 项目闭包/旧版归档 | 永久 | 只写不改，入库即定稿 |
| **Project** | 当前项目动态追踪（行动锚点） | 项目周期内 | 收工更新，完结归档 history |

**存储位置**：实际内容一律在 `mind-private\L3\`（隐私，永不推送）。`mind\L3\` 只保留模板与出厂示例。

## 二、index 规则

### 文件命名
`YYYY-MM-DD_描述.md`（迁移记忆可保留原名）

### 覆写规则
- 已有文件：**增量覆写**（保留原有信息追加），不追加补充文件
- 层级结构调整（重组章节/改分类）须用户确认
- 错误更正：原文修正，文件头标注 `(YYYY-MM-DD 修正)`

### 新建规则
1. 轮级缓冲写草稿 → 2. 按 §八 溯源门禁判定（有源直落 / 无源标 verified:false / 敏感·拿不准 → pending 等用户裁决）→ 3. 写入 `mind-private\L3\index\<主题>\` → 4. 更新该目录 `_index.md` → 5. 更新 Tree.md

### 删除规则
- 仅用户明确说"删除 xxx"时执行；删除前确认是否被引用

## 三、history 规则

- 命名：`YYYY-MM-DD_第{n}季_{标题}_全文留档.md`（或 `YYYY-MM-DD_<标题>_归档.md`）
- **只写不改**——时间是单向的；更正追加新记录，不修改已归档文件
- 每个子目录维护 `_index.md`：`| 日期 | 文件 | 类型 | 摘要 |`

## 四、Project 规则

### 入口文件（每个项目必须有 project.md）
```markdown
# 项目名 — 项目档案
> 类型 / 版本 / L2依赖 / L3引用 / 路径
## 项目目的
## 项目周期
## 进度状态（子步骤级：✅/🔧/🔵/🟡）
## 素材清单
## 下一步
```

### 上工加载
1. 检索可用项目（从 Tree.md「Project 清单」）→ 2. 一句话列出（项目名·阶段·状态）→ 3. 等用户指令「加载 XX」→ 4. 读 project.md + 🔴 强制依赖文档 + 待办

### 收工更新
- 进度状态标注到子步骤级；版本 +0.1；日期更新；完结时归档 history 并从 Project 移出

## 五、蒸馏沉淀规则（L2→L3）

- **触发**：L2 Exp/Skill 踩坑 ≥3 条且同主题
- **流程**：识别主题 → 草稿（问题→根因→对策→判例）→ 按 §八 溯源门禁判定（有源直落 / 无源标 verified:false）→ 写入 `L3/index/<主题>/` → L2 加引用 → 更新 Tree.md
- **红线**：L3 沉淀后 L2 原始踩坑保留不删（L2 快速参考，L3 深度查询）；同主题多次沉淀增量覆写

## 六、TRASH 规则

- 不删除，除非用户明确要求；移入时同步更新 Tree.md 与 TRASH/_index.md（首次移入时若无则建——懒创建，非上工必读）
- TRASH 文件不参与知识加载；恢复 = 移回原路径

## 七、与 mind-private 的边界

- 出厂模板在 `mind\L3\`；**运行时记忆一律写 `mind-private\L3\`**（同名私有优先）
- 隐私红线：真实记忆内容永不写入出厂区、永不推送

## 八、记忆写入门（溯源信任 + 可选审阅）

> 哲学：信任靠溯源挣来，不靠人审预设（`mind\L1\Design-Philosophy.md`）。记忆进 L3 不再强制经人审。
> **日期锚**：条目/教训的日期以上工召回【系统日期】（机器时钟）为准——不自猜、不沿用旧文件日期（2026-09-06 全库超前错标 2 天教训，09-04 已校正）。
> 溯源契约（确定性内核，`mind-validate` §② 强制）：每条 L3 记忆 frontmatter 必须带 `source` **或** `verified: false`——二者至少其一。
> `source` = 外部可查证依据：文件 / 事件 / 用户明示 / 实测；**agent 自推理不算 source**（无 source 的自推理一律标 `verified: false` 降权）。
> **importance 判据（检索权重的质量分，写入时自评）**：绑**可观察事实信号**，不凭"我觉得重要"拍脑袋。五档语义——

| 分 | 语义 | 判据（可操作，宁低勿高，默认 2） |
|---|---|---|
| 5 | 关键 | **违反它代价大 / 高频依赖**：隐私红线、宪法条款、核心方法论——丢了会出事 |
| 4 | 重要 | **跨主题/跨项目复用**：多个场景都在用的设计决策、通用流程 |
| 3 | 常规 | 单主题内常参考：踩坑对策、领域知识 |
| 2 | 参考 | 特定场景才查：细节速查、背景资料（默认档） |
| 1 | 边缘 | 几乎不再用 / 可被替代——查到算赚，查不到不亏 |

> 自评问题：「丢了它，最坏会怎样？」代价大 → 5；没代价 → 2。**后果严重度 > 新鲜感**。用户明示「这个很重要」= 直接 5。importance 是写入时质量分，作为检索排序的分量之一（参与 §十 排序：相关 + 可信度 + scope + importance，见 `packages/dshome-mind/lib/index.cjs` searchMind），不引入自动热度计数——热度是流行度噪声，importance 才是分量信号。

> **importance 调整规则（重评事件驱动，不做定时重评）**：评分不是一次定终身——记忆被复用/过时/发现高估时该升该降。**谁能调**：鱼鱼主动重评（按事件）；主人随时直接改 frontmatter 或明示「这条很重要/没用了」→ 主人明示 = 最高优先级，直接定档。**何时调（只在这 4 类事件触发）**：

| 触发事件 | 方向 | 判据 |
|---|---|---|
| 记忆被**复用/引用**（检索命中后真解决问题、被 skill/其他记忆 related） | ↑ 升 | 「它真的频繁在帮我干活」 |
| 记忆**内容过时/被替代**（新记忆覆盖、方案废弃） | ↓ 降 | 「它不再代表现状」 |
| 使用后发现**没那么关键**（当初 5 分实际少依赖） | ↓ 降 | 「丢了它的最坏后果」重估变小 |
| 主人**表态**（很重要/没用了/调成 X） | 按主人 | 主人明示直接定档 |

> **两条纪律（防抖动）**：① **事件驱动，不做定时重评**——不搞「每周给所有记忆重打分」，那是温度计的变体（繁冗罪）；② **调整后进冷静期**——同一条调完分，无新强信号不短期反复改（防「今天 5 明天 2」手抖）。调整本身 = 内容变更，按 §二 覆写规则走（增量覆写 + git/快照留痕），不另设日志字段。

- **有源可溯 → 直接落库**：记忆带 `source`（外部可查证依据：文件/事件/用户明示/实测，非 agent 自发推理）→ 写 `L3\index\<topic>\`（frontmatter：kind/importance/scope/topic/tags/source/proposedBy/proposedAt），即时生效，信任靠溯源。
- **无源 / 自推理 → 标 `unverified`**：写 `L3\index\<topic>\` 但 frontmatter 加 `verified: false`，**不参与权威裁决**（降权，可被有源记忆覆盖）。
- **存量迁移**：旧记忆（无 frontmatter / 用 `> date:` 引用式头）迁移时补 frontmatter；内容有出处 → 提为 `source`；确无外部依据 → 标 `verified: false`。校验不过即阻塞提交，不接受"先记着"绕过。
- **用户明示 / 敏感 / 拿不准**：才建议走 `mind-private\tasks\pending\<日期>_<名>.md` 等用户在图谱面板「⏳ 待放行」裁决（✓ 入库 / ✗ 入 TRASH）；**非强制门**，仅作可选审阅。
- **例外**：用户**直接要求记录**（"记一下/存下来"）→ 实时落盘，不入 pending。
- 🔍 **写入前自查（防重复）**：提议任何记忆前，先查同主题是否已有同一事实——`/api/mind/dup-check { topic, content }` 返回相似命中（bigram-Jaccard，≥12% 提示）。有高置信重复（≥30%）→ **不新增**，汇报"已有 X 相似 N%，更新旧条目还是新增？"；低分命中看 snippet 判断。目标：同事实只存一份

## 九、整理队列（curate-jobs，内容级处置委托）

- **触发**：用户在整理区对候选点「🤝 让鱼鱼处理」→ 后端写入 `mind-private\.curate-jobs.json`（{ file, at, status: assigned }）
- **执行**：鱼鱼收工闭环检查该文件——按候选 reason 做内容级整理：
  - `oversized`：蒸馏速查 / 拆分冗余（冗余内容入 history）
  - `thin`（合集）：并入同主题主文件或补全
  - `dup-tags` / 疑似重复：比较合并，保留更好的一份
- **完成**：移除 job + 文件记入 `.curate-kept.json`（不再提示）+ 汇报用户处理结果
- 边界：归档（整文件入 history）与保留（忽略）是用户自己在面板做的事；内容级改动才走此队列

## 十、记忆调取与评价（排序规则）

> ⚠️ **这节是该系统"给别人用"的关键**（公开仓库/传给别人/发视频）：记忆的评价必须**可解释、通用、诚实**——别人打开能看到"这条为什么靠前"，而不是玄学分数。
> 核心：**记忆优先级 = 它值不值得优先调取**，由 4 个维度综合判断，**粗分级、随真实事件修正、非热度**。

### 调取一条记忆前的判断（前 3 维，调取时判定）

| 维度 | 问什么 | 分级 | 用途 |
|---|---|---|---|
| **相关度** | 这条跟当前问题相关吗（相似度） | 超过阈值才算"相关" | **检索第一闸**，不相关不调取（用 bigram-Jaccard） |
| **可信度** | 这条有据/验证过，还是推理？ | A 有据 / B 已验证 / C 待验证 | 决定"能不能当权威用"；C 级**不主动调取**、只作参考 |
| **时效性** | 这条现在还有效吗？ | 有效 / 过时 / 被替代 | 过时/被替代 → 降权、归档 |

### 调取记住一条后（第 4 维，事后修正）

| 维度 | 问什么 | 分级 | 用途 |
|---|---|---|---|
| **有用度** | 用了它真的帮到解决问题了吗？ | 常有用 / 偶有用 / 没证过有用 | **修正以后排序**——但**不是"用了多少次"（热度），是"有没有真解决"** |

### 排序规则（综合，粗分级不精细计分）

```
优先调取：相关且 A/B 级且有效
  同级内：scope（user > self > project）> importance > 相似度(微调)
不主动调取：C 级（待验证）、过时/被替代
事后修正：被证有用 → 升；误导/被推反 → 降权
```

### 关键边界（对外可解释）
- **不用"热度"**（用了多少次）——常用≠重要，会自我强化。
- **不搞精细分数**（1-100）——分太细是"假装精确"，分不出就是欺骗。
- **每条变化都有依据**：找到来源→升；被验证→升；被推翻→过时→降。**别人看得到"为什么变"。**
- 本规则是 L1 公开版（出厂区，可解释给所有人）；**实际记忆数据仍在 `mind-private\L3\`（隐私）。**

> ⚠️ **实现状态（诚实标注）**：目前 `searchMind` 已实现"**相关 + 可信度(A/B/C) + scope + importance**"排序；"**时效性**（有效/过时/被替代）"与"**有用度**（反馈修正）"**待真实信号接入**——现在无"过时/被替代"字段、也无"调用后是否有效"反馈通道，强行实现只是空壳。**等这两类信号能采集时再补**，不假装已实现。
