# Memory.md — L3 规则书

> 版本：1.0 | 2026-09-02 | 初版（参考 Cathome Memory v2.0 蒸馏）
> 加载：强制层（每次上工必读）
> 定位：L1 海马体——定义 L3 index/history 与 Project 的归档规则。L3 引用 Memory 来规定自己。

## 一、L3 三种类型边界

| 类型 | 定位 | 生命周期 | 修改规则 |
|---|---|---|---|
| **index** | 结晶知识（踩坑沉淀/设计/速查） | 持续积累 | 增量覆写，删除须用户确认 |
| **history** | 项目闭包/旧版归档 | 永久 | 只写不改，入库即定稿 |
| **Project** | 当前项目动态追踪（行动锚点） | 项目周期内 | 收工更新，完结归档 history |

**存储位置**：实际内容一律在 `mind-private\L3\`（隐私，永不推送）。`mind\L3\` 只保留模板与出厂示例。

## 二、index 规则

### 文件命名
`YYYY-MM-DD_描述.md`（迁移记忆可保留原名）

### 覆写规则
- 已有文件：**增量覆写**（保留原有信息追加），不追加补充文件
- 层级结构调整（重组章节/改分类）须用户确认
- 错误更正：原文修正，文件头标注 `(YYYY-MM-DD 修正)`

### 新建规则
1. 轮级缓冲写草稿 → 2. 用户确认 → 3. 写入 `mind-private\L3\index\<主题>\` → 4. 更新该目录 `_index.md` → 5. 更新 Tree.md

### 删除规则
- 仅用户明确说"删除 xxx"时执行；删除前确认是否被引用

## 三、history 规则

- 命名：`YYYY-MM-DD_第{n}季_{标题}_全文留档.md`（或 `YYYY-MM-DD_<标题>_归档.md`）
- **只写不改**——时间是单向的；更正追加新记录，不修改已归档文件
- 每个子目录维护 `_index.md`：`| 日期 | 文件 | 类型 | 摘要 |`

## 四、Project 规则

### 入口文件（每个项目必须有 project.md）
```markdown
# 项目名 — 项目档案
> 类型 / 版本 / L2依赖 / L3引用 / 路径
## 项目目的
## 项目周期
## 进度状态（子步骤级：✅/🔧/🔵/🟡）
## 素材清单
## 下一步
```

### 上工加载
1. 检索可用项目（从 Tree.md「Project 清单」）→ 2. 一句话列出（项目名·阶段·状态）→ 3. 等用户指令「加载 XX」→ 4. 读 project.md + 🔴 强制依赖文档 + 待办

### 收工更新
- 进度状态标注到子步骤级；版本 +0.1；日期更新；完结时归档 history 并从 Project 移出

## 五、蒸馏沉淀规则（L2→L3）

- **触发**：L2 Exp/Skill 踩坑 ≥3 条且同主题
- **流程**：识别主题 → 草稿（问题→根因→对策→判例）→ 用户确认 → 写入 `L3/index/<主题>/` → L2 加引用 → 更新 Tree.md
- **红线**：L3 沉淀后 L2 原始踩坑保留不删（L2 快速参考，L3 深度查询）；同主题多次沉淀增量覆写

## 六、TRASH 规则

- 不删除，除非用户明确要求；移入时同步更新 Tree.md 与 TRASH/_index.md
- TRASH 文件不参与知识加载；恢复 = 移回原路径

## 七、与 mind-private 的边界

- 出厂模板在 `mind\L3\`；**运行时记忆一律写 `mind-private\L3\`**（同名私有优先）
- 隐私红线：真实记忆内容永不写入出厂区、永不推送

## 八、pending 待放行协议（记忆写入门）

- **流程**：提议记忆（鱼鱼识别到值得长期记的结论）→ 先写 `mind-private\tasks\pending\<日期>_<名>.md`（frontmatter：kind/importance/scope/topic/tags/proposedBy/proposedAt）→ 用户在图谱面板「⏳ 待放行」区逐条操作
- **放行 ✓** → 移入 `L3\index\<topic>\`（记得更新该主题 `_index.md`）
- **拒绝 ✗** → 移入 `mind-private\TRASH\`（不删只移，可恢复）
- **为什么**：不自动落正式库——记忆要经用户点头（对应 dsh-evolve 时代的审批门，纯文件实现）
- 例外：用户**直接要求记录**的内容（"记一下/存下来"）→ 实时落盘，不进 pending
- 🔍 **写入前自查（防重复）**：提议任何记忆前，先查同主题是否已有同一事实——`/api/mind/dup-check { topic, content }` 返回相似命中（bigram-Jaccard，≥12% 提示）。有高置信重复（≥30%）→ **不新增**，汇报"已有 X 相似 N%，更新旧条目还是新增？"；低分命中看 snippet 判断。目标：同事实只存一份
