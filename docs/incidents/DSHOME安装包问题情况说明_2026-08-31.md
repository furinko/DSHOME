# DSHOME v0.2.0 安装包问题情况说明

- **日期**：2026-08-31
- **环境**：Windows 11（x64）
- **产品版本**：DSHOME v0.2.0（安装包 `DSHOME-setup-0.2.0.exe`，约 218MB）
- **结论先行**：安装包为 **7-Zip SFX 自解压包**，包内预置的 `profiles\node_modules`（dsh 运行时自愈目录）经打包/解压后**符号链接（junction）全部实体化**，导致 dsh 后端启动自检失败。**安装包可用，但打包流程存在缺陷**，需在打包侧修复（见第 7 节）。

---

## 1. 背景

在完全清理设备上全部 dsh/DSHOME 旧内容（进程、目录、计划任务、快捷方式、注册表、环境变量零残留）后，于**干净环境**下测试 DSHOME 安装包的首装体验。

## 2. 复现步骤

1. 从 GitHub Release（furinko/DSHOME，v0.2.0）下载 `DSHOME-setup-0.2.0.exe`；
2. 双击运行安装包，内容展开至 `E:\DSHOME`（根目录全部文件同一秒创建，为解压展开特征）；
3. 双击 `E:\DSHOME\开发启动.cmd` 启动；
4. Electron 壳弹出错误弹窗：**「后端连续 3 次启动失败，可能由插件或配置损坏引起」**。

## 3. 错误信息（完整堆栈）

弹窗截断了堆栈，手动启动后端获取完整错误：


## 4. 定位过程

1. 确认安装形态：`DSHOME-setup-0.2.0.exe` 文件头/尾部含 **7-Zip** 特征字符串，为 **7-Zip SFX 自解压包**（非 Inno Setup：无注册表卸载项、无安装日志、无 `install.env`/`launch.cmd`）；
2. 阅读 `@deepseek-ai/dsh-app-boot` 源码（`healProfilesModuleFallback` / `ensureSymlink`，lib/index.js:370-438）：
   - dsh 每次启动会维护 `$DSH_HOME/profiles/node_modules` 作为**扁平模块 fallback 目录**；
   - 对 dsh 应用依赖闭包（BFS 遍历 dependencies + peerDependencies）中的**每一个包**，要求该目录下对应条目为 **symlink/junction**，指向包的真实位置；
   - 若条目存在但不是 symlink（实体目录/文件）→ **直接抛错拒绝启动**（设计上要求人工删除，由 dsh 重建链接）；
3. 实测 `E:\DSHOME\profiles\node_modules` 为 **168MB 实体目录树**（含 @aws-sdk、express 等数百个真实复制目录，而非链接）。

## 5. 根因分析

- **安装包内预置了 `profiles\node_modules`**（约 168MB 实体树）。该目录本应属于 dsh 的**运行时自愈目录**——首次启动时由 `healProfilesModuleFallback` 自动生成全部 junction，无需（也不应）随包分发；
- **7-Zip 打包/解压不保留 Windows junction 语义**：7z 归档不保存 NTFS junction 属性，打包前为链接的条目在解压后变为完整实体复制；
- 两者叠加：解压后的 `profiles\node_modules` 全为实体目录 → dsh 启动自检对依赖闭包内每个包逐一校验 → 命中实体目录即报 `exists and is not a symlink` 并退出（每删除一个，校验继续报下一个，直至全部清空）。

> 与具体机器、网络、配置无关，属于**包内结构问题**——任何用户通过该 exe 安装都会复现。

## 6. 修复（已验证）

1. 删除 `E:\DSHOME\profiles\node_modules`（实体复制树）；
2. 重新启动后端；
3. dsh 启动自愈机制自动为依赖闭包重建全部 junction（Windows junction 无需管理员权限）；
4. 验证通过：
   - 端口 3099 LISTENING；
   - `Invoke-WebRequest http://127.0.0.1:3099` 返回 **HTTP 200**；
   - `Get-Item E:\DSHOME\profiles\node_modules\@deepseek-ai\dsh` → `LinkType: Junction`，Target 指向根 node_modules 真实位置；
   - Electron 壳正常拉起，应用完整可用。

修复耗时约 1 分钟，**用户侧应急办法**：遇到同款错误时，删除 `profiles\node_modules` 后重启即可（dsh 自动重建）。

## 7. 根治建议（打包侧）

1. **打包时排除 `profiles\node_modules`**（建议在 build 脚本的 staging 组装中显式排除，与 `.gitignore`/`sessions`/`storages` 同级处理）——该目录由 dsh 首次启动自动生成，不应进包；
2. 若必须预置，需评估打包工具的链接语义支持：7-Zip SFX 不保留 junction，Inno Setup 等安装器同样需要验证；
3. **发布流程加入安装后冒烟验证**：静默/自动安装 → 启动 → 断言 HTTP 200 + `profiles\node_modules` 条目为 Junction，作为 CI/发布门禁；
4. 本次问题已沉淀至运维手册（构建/打包/修复/识别方法），后续版本构建前先核对。
