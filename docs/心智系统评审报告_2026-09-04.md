## 1. 结论

**综合得分：≈ 7.6 / 10（B+）**

一句话评价：**这是一个真正认真、且对自己诚实的心智系统。** 它追求的确实是"别自信地错"（而非"更聪明"），这从它的自我批判记录（那些"我又直接动手了""我又顺着用户暗示走"）里能真实看到——它在长，不是嘴上说说。

**但它的真实短板不是"想得不够深"，而是"证据跟不上机制"。** 文书层做得很足（L0 3 文件 · L1 10 文件 · L2 5 技能 · 收工 9 步 · 自省 7 问 · 固化门禁 4 条 · 可测信号 5 个 · 自进化 117 条记录），但**信号数据层极浅**：5 个可测信号里 4 个是 0，117 条进化记录 0 次无效。机制比喂给它的证据多得多。

核心骨架（双区、语义层、护栏、注入）是**真实落地、可运行、有版本历史撑腰**的，不是纸面系统。

## 3. 设计优点（最值得保留的部分）

1. **"依据唯一"纪律是真的在收敛。** 待办/进度/建议/记忆/技能五概念注册进 `Concepts.md`，其它文档**只引用不重复定义**；`AGENTS §四` 明确"本表其余行仅常用速查，勿重复定义"。这是治理"知识互相打架"的根本正确方向，且 `index.cjs` 有对应后端。

2. **自省尺重构（七德七罪→行为问题尺）是难得的自觉。** `Design-Philosophy.md §六` 明确点破品格名词"没刻度/名词而非行为/贴标签/病药混"，改成可答"是/否"、有判据、指向改动作的行为问题。这是少数能对自己方法论做"第二序批判"的系统。

3. **"别把花朵压死"的分寸感。** `Design-Philosophy.md` 把"防毒/防自欺"设成唯一硬底座，明确反对把"防错/失控/冗余"也做成厚重门禁——防"护栏长成监狱"的高质量哲学判断，且 `mind-guard` 确实只留 2 条真拦、生长区全放行，**言行一致**。

4. **自进化档案（快照+log+回滚）与"固化门禁+验证期"。** 改自我类文件前要快照、改后要 `mind-validate`、失败回滚——真实解决"agent 改坏自己"问题的机制，不是口头承诺。

5. **诚实标注未实现部分。** `Memory.md §十` 明说"时效/有用度待信号接入，现强做只是空壳"。这种自我承认，在这类系统里非常罕见，最能降低被误导风险。

## 4. 真实缺陷与风险（附证据，按严重度排）

### 4.1 【高】自进化的"效果验证闭环"基本没运转
- `evolve-log health`：**117 条进化记录，但"无效回测 0 条"**；5 个可测信号里 `corrections=2`，其余 `repeat-mistakes=0 / rejections=0 / redos=0 / search-hit=0`。
- 含义：系统做了一大套"快照+log+effect 回填+可测指标"的**自我验证机制**，但**实际从未做过一次"无效→回滚"**，effect 几乎没被回填。健康检查自己也报了"进化记录偏多→审视僵化"。
- **判断**：机制外壳做得很足，但"让进化可验证"的数据层近乎闲置。**自我强化**风险——记录一直在涨，却几乎没有一次被证明无效而砍掉。（好消息：它自己嗅到了，`Power.md §七` 元进化体检就是为此准备——但目前只是"提示了"，没真做深度体检。）

### 4.2 【高】`mind-validate` 的 (c) 校验是死代码 —— AGENTS 双版本漂移现已无人看守
- `mind-validate.mjs:227-229`：`if (existsSync(root) && existsSync(payload))` 才跑 (c)。但 root `AGENTS.md` 已于 09-04 删除 → 条件恒假 → **(c) 永远不会执行**。
- 而权威版 `mind\L0\AGENTS.md` = **6621 字节**，`build-stage\payload\AGENTS.md` = **6491 字节** —— **当前就是漂移的**，却没有任何检查能发现它。
- **判断**：AGENTS.md 声明的三类结构性校验（含 AGENTS 双版本）里，双版本这项实际已失效。

### 4.3 【中】版本号四处不一致，且无人检查
- `boot-recall.md`：`Tree.md` 清单写 **1.0.0**，`_index.md` 写 **1.0.1**，文件 frontmatter 写 **1.0.1**，文件尾 `_版本` 写 **1.0.0**。
- `Power.md §六` 明文"文件头版本与文件尾版本一致"，`mind-validate` 却**不检查**头尾一致性，只查 header 键与 Tree/_index 的**文件名集合**。
- **判断**：规则立了，但断言的"版本一致性"没有机器兜底，当前已违反。

### 4.4 【中】`mind-prime --limit` 参数是坏的（实测）
- `mind-prime.mjs:18`：`args.find(a=>a.startsWith('--limit'))` 返回的是单字符串 `'--limit'`，再 `.split(' ')[1]` 得 `undefined` → 恒 fallback 5。
- 实测传 `--limit 10` 仍按默认 5 处理。**文档说可 `--limit` 调，实际无效。**

### 4.5 【中】检索逻辑重复实现，有漂移风险
- `tokenize/jaccard/search` 在 `scripts/mind-prime.mjs` 和 `packages/dshome-mind/lib/index.cjs` 各写了一份，行为不完全一致（阈值/排序略有差异）。
- 这是"权威源唯一"原则在**代码层**的反例：文档层靠 Concepts 收敛，代码层检索却双头。

### 4.6 【低】技能描述与实际小出入
- `_index.md` 中 `boot-recall` 版本为 1.0.1，与 `Tree.md` 的 1.0.0 不符（见 4.3）。

## 5. 更深层两个结构化问题（设计张力，不全是 bug）

### 5.1 形式深度 < 实质数据深度
这套系统在**文书层**做得很深，但**信号数据层**极浅：5 个可测信号里 4 个是 0，只 `corrections=2`；117 条进化记录 0 次无效。**机制比喂给它的证据多得多。** 当证据远不足以支撑这么多机制时，风险不是出错，而是**每个机制都在消耗 token / 注意力 / 维护成本，却无法证明自己有用**——这恰恰是系统自己最怕的"机械过重"。

### 5.2 "自我治理"与"最低消耗/少而精"的内在冲突
`AGENTS/TOOL/SOUL` 三处都喊"最低消耗、一句话说清、省 token"。但 `Power.md §九` 挂了 **14 条行为纪律**（蒸馏闭环/元进化/自主洗澡+巡视/极限记录/前瞻点子区/写前查重/整理队列/cron 自治/进化档案/可测指标/多模型会诊/只存蒸馏结论/复盘自己/固化门禁/自我修改事务门禁）。**少而精的哲学 vs 事无巨细的纪律清单**，张力真实存在。系统试图用"常驻极简 + 按需读 §九"调和（注入层只有 ~389 token），这是正确的调和思路，但 §九 本身仍偏重。

## 7. 优先修复建议（按价值排序）

1. **让自进化真正产生"effect"数据** —— 每次自我改动后，在下一次相关场景出现时**强制回填一次**（有效/无效），先让 0 变成有意义的非零。不然 117 条只是账本，不是记忆。
2. **修 `mind-validate` 的 (c)** —— root AGENTS 已删，应改为对照 `mind\L0\AGENTS.md` 权威版 vs `build-stage\payload\AGENTS.md`，并在打包时强制同步 payload（当前两者已差 130 字节）。
3. **给"版本号一致性"补机器检查** —— Tree/_index/frontmatter/footer 四者比对，把 `Power.md §六` 那条规则从"靠自觉"变成"自动拦"。
4. （可选，低优先）修 `mind-prime --limit` 解析；统一检索逻辑为单一实现。

### §7-4b 检索归并为何"评估后不做"
- **事实**：`scripts/mind-prime.mjs` 与 `packages\dshome-mind\lib\index.cjs` 的 `tokenize/jaccard` **逐行一致**（CJK bigram + `[a-z0-9]` regex 相同），当前**无实际漂移**。
- **评估**：单头归并需抽共享模块并让两处 import——`index.cjs`（宿主运行时插件）与 `mind-prime.mjs`（独立 CLI）跨 ESM/CJS，改动会动宿主插件结构、有重引用/运行时风险（`mind-guard.js` 注释明确警告"不 require index.cjs"）。而收益是"防范未来漂移"，非修复现有问题。
- **结论**：此为"过度工程防患于未然"，与系统 `Design-Philosophy.md`「别把花朵压死 / 少而精」一致，**不满足"该修"**，故记为评估记录而非待办。若未来两份实现出现实质漂移，再单头归并。
