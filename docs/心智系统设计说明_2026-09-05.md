## 〇、一句话定位

DSHOME 的心智系统**不是记忆仓库，而是一个能自我验证、自我沉淀、自我进化的认知系统**。它的首要追求刻意设为**「别自信地错」**，而不是「更聪明」——这从 `mind\L1\Design-Philosophy.md` 的立论和它自己的自我批判记录里能真实看见。

> 关键分界（`Design-Philosophy.md` §二）：**生长**要全放开（不预设长成什么样、不留死 schema）；**知识底座**只守一条硬线——**防自欺**（记忆要么有源可溯、要么诚实标"未验证"）。防「错/失控/冗余」这些**如果不加区分地做成硬门禁，就会把花朵压死**。

## 一、为什么存在（设计初衷）

`mind\L1\HUB.md` §一 一句话立意为「被蒸馏过的逻辑结晶」——把「怎么想」和「怎么做」分离、归类、索引、版本化。四个存在价值：

1. 让每次决策有据可查，**不依赖「我记得」**
2. 让每个技能可跨项目复用，**不被上下文遗忘**
3. 让每个灵感有家可归，**不在对话流里蒸发**
4. 让 DSHOME 不只是聊天工具，而是**能自我进化的认知系统**

## 二、双区知识基座（隐私边界的基石）

这是整座系统最硬的一条红线（`mind\L0\AGENTS.md` §三、`mind\README.md` §三）：

| 区 | 是什么 | 能否推送 |
|---|---|---|
| `mind\` | 出厂固件（架构 + 默认内容） | ✅ 可推 GitHub |
| `mind-private\` | 本机运行时自进化（真实记忆/项目/偏好） | ❌ `.gitignore` 永不推 |

- **同名文件私有区优先**——加载时规则从 `mind\` 读，记忆和项目从 `mind-private\` 读。
- 私密数据（凭据/隐私/敏感业务）**只进 `mind-private\`**，永不写入出厂区。

> 实机核验（`心智系统评审报告_2026-09-04.md` §2）：`git ls-files mind` = 25 文件、`git check-ignore mind-private` 命中、`.gitignore:42` 存在——边界真实成立。

## 四、三层加载模型（token 预算的管理核心）

**这是全文的唯一权威，在 `mind\L1\HUB.md` §三**（各文档只指指针，不重复维护）：

```
注入层（系统提示词，随每轮携带）：L0 三文件 + L1/HUB
强制层（每次上工必读）：Tree / Power / Memory / Learn / Invariants
查询层（按需）：Concepts/DP/Dream/Ritual/Wisdom + L2/L3/Project 按需 grep/read
```

设计意图：**常驻极简 + 细则按需**。把最贵的 token 预算花在「注入层」——每次会话都要带着的灵魂与铁律；而 Tree（有什么）、Power（怎么用）、Memory（怎么存）、Invariants（不可绕过）是强制层；其余更重/更少用的文档全进查询层，用到才读。

## 六、语义层 / 概念注册表（Concepts.md）—— 治「知识打架」

这是心智系统的一个**关键架构补强**（2026-09-03 语义层落地）。核心是**「依据唯一」纪律**：

- **概念注册表**：`todo / progress / suggestion / memory / skill` 五个概念的**唯一权威源**挂号处。其它一切文档**只引用本表、不得各自重复定义**。
- **意图 → 概念 → 权威源 路由表**：把「我想下一跳/进度/建议/记忆/技能」路由到唯一入口。
- **撞名消歧表**：一个词命中多个候选对象时**先钉身份再动手**（如 `DSHOME` 可能指产品/心智系统/心智图谱面板，按上下文判定）。
- **薄契约 + 开放正文**：只结构化「系统要判断/查询/流转」的字段，`status/priority` 用**开放标签不设死枚举**，正文自由——这是「全放开生长」在语法层的落法。

> 实机核验：`packages/dshome-mind/lib/index.cjs` 的 `searchMind/readTodos` 与 Concepts 路由表对应——语义层有后端支撑，不是纸面。

## 七、确定性内核 vs 判断层（Invariants.md）—— 分界

类比 CH4 的「确定性运行时 vs LLM 表达」。**判断层**（归类/方案/内容/从哪下手）归 LLM 自由发挥；**确定性内核**是**永远不该被 AI 判断绕过的硬约束**，每条带门禁/兜底。核心不变式（🔴 硬约束 / 🟡 防依赖）：

- 🔴 隐私红线；🔴 先搜后写；🔴 指令原子性；🔴 方案确定 ≠ 获准实施；🔴 不覆盖（冲突进 TRASH）
- 🟡 记忆溯源降权；🟡 写前查重（≥30% 不新增）；🟡 进化档案（改前快照+log）；🟡 只存蒸馏结论；🟡 收工闭环；🟡 交付前自检

**门禁链**：发起行为 → 过确定门禁（隐私？先搜？等放行？要快照？要查重？）→ 全过才执行，任一不过就停下/提问。规则：**判断层可以自由，但任何判断不得违反确定性内核**。

## 八、记忆系统（Memory.md）—— 三层 + 溯源信任模型

L3 分三种记忆，生命周期和修改规则不同：**index**（结晶知识，持续积累）、**history**（时间胶囊，**只写不改**）、**Project**（行动锚点，收工更新/完结归档）。

其中最核心的**溯源信任模型（§八）**，是防自欺底座的实现：

- **有源可溯 → 直接落库**：`source` = 外部可查证依据（文件/事件/用户明示/实测），**agent 自推理不算 source** → 即时生效，信任靠溯源。
- **无源 / 自推理 → 标 `unverified`**：落库但 `verified: false`，**不参与权威裁决**，降权可被覆盖。
- **用户明示 / 敏感 / 拿不准 → 可选审阅**：才走 `pending\` 等用户在面板裁决——**非强制门**。
- **用户直接要求记录 → 实时落盘**，不入 pending。
- **写前自查（防重复）**：`/api/mind/dup-check`（bigram-Jaccard），≥30% 相似不新增，先汇报「更新旧条目 or 新增」。

**调取评价（§十）**——因为要「给别人用/可解释」：记忆优先级由 **相关性（检索第一闸）→ 可信度（A有据/B已验证/C待验证）→ 时效性** 前三维在调取时判定，**有用度**事后修正；排序 `scope(user>self>project) > importance > 相似度`。明确**不用热度**（常用≠重要，会自我强化）、**不搞精细分数**（分太细是假装精确）。且**诚实标注**：时效性/有用度目前待信号接入，强做只是空壳——这种自我承认正是它降低误导风险的地方。

## 九、行为执行面 —— 把「靠提醒」升级为「机器拦」（最容易被忽略的设计）

这正是心智系统区别于「知识库+加载层」的关键：它有个**行为执行面**，由 host 插件 + 脚本构成，把行为约束从「提醒鱼鱼」变成「真拦」。

### 1. 注入插件 `dshome-mind-inject`（`packages\dshome\lib\host\mind-inject.js`）
- 每个 agent 会话**开始（第一步）**时往消息流塞一条「心智 L0 摘要」user 消息（照官方 `agent-instructions` 同构机制，走 `ctx.on('agent/pre-step')`）。
- **每会话只注入一次**（按 session 去重），不是每轮。
- 载荷是**手写 `L0_SUMMARY`（形态A，~388 token）**——抛弃了关键词抽取（旧机制脆弱、随措辞漂移，曾实测抽成空壳/被截断丢纪律）。**只装「每次会话都该遵守」的核心；权威正文仍在 `mind\L0\AGENTS.md`，不重复。**
- fail-open：注入失败只记日志，绝不阻断。

### 2. 护栏插件 `dshome-mind-guard`（`mind-guard.js`）
用官方 `ctx.tools.guard()` 在 `write/edit/str_replace_editor` **真正写入前**判一次，**只做拦不做注入**（单一职责）。内核极窄，按「**是否改行为规则**」分层：

- **① 隐私红线（真硬拦）**：往出厂区 `mind\L0/L1/L2/README` 写**疑似私密数据**（`api_key/secret/password/.pem` 等）→ 拦。
- **② 自我修改门禁（高危真拦 / 技能提示 / 文档放行）**：
  - **高危**（L0 三件 + `HUB/Wisdom/Memory/Power/Invariants/Design-Philosophy`）→ 无放行记录则**真拦 + 写 pending** 供「心智 → 动作放行」面板裁决；
  - **技能 L2 / 自身记忆 `private L1`** → 只提示不拦（日常生长）；
  - **README/Tree/Concepts/Dream/Learn（文档·索引·记录）** → 直接放行。
- **③ 等放行不做硬拦**——程序判不了「用户意图」，硬拦易误伤（违背「别把花朵压死」），保留提示+记录。
- 放行记录 `mind-private\tasks\approvals.json`：**一次性消费**，命中即删（下次改同文件需重新裁决，**不永久放行**）。

> 特别地，高危名单从「整目录」收窄为「精确规则文件」，修复了一个真实缺陷：**新增记忆要更新 `Tree.md` 索引，若按目录划高危会误拦正常的索引更新——生长动作被自己的护栏掐断**。

### 3. 上工自动召回 `scripts/mind-prime.mjs`
上工时装配 `project.md` 进度 + 下一步 + 相关 L3 + 最近教训 + user-rules 成注入上下文；`mind\L2\Skill\boot-recall.md` 描述其行为；无档时优雅降级。B3 闭环：无 `project.md` 时**当场按模板初始化一份**（解开「收工 step1 假定档已存在」的鸡生蛋）。

### 4. 自我修改硬流程（三件事同时满足才落盘，`AGENTS.md` §五 + `Ritual.md` §四）
1. **用户放行**（高危区经护栏面板 ✓；技能/自身记忆按门禁自主走）
2. **改前快照**（`node scripts/evolve-log.mjs snapshot <file> "<理由>"` → `snapshots\`）
3. **改后 `mind-validate.mjs` 通过**——结构校验含 **Tree↔_index↔实际同步 / 权威源单一 / AGENTS 双版本** 三类，`--strict` 全绿才提交；校验失败 → **回滚快照**。

## 十、自进化（它是「活的」而非「记得的」）

`Ritual.md` 把进化做成**可验证、可回滚、可自我审视**的机制：

- **进化档案**：改自我类文件前 `snapshot` + `log`，改后进观察期用 `effect` 回填有效/无效——**有效则沉淀，无效则回滚**（快照在 `evolution\snapshots\`）。
- **可测指标**：`evolve-log bump <信号>` 记硬证据（`repeat-mistakes/corrections/rejections/redos/search-hit`），用 `evolve-log metrics` 看当前值——「变好了」要有硬证据，不靠感觉。
- **自主三件套**（cron 自治）：
  - 🐟 `self-feed`（成长，每周，有货才吃）
  - 🚿 `self-clean`（洗澡+巡视，每天零点；洗自己弄脏的，**不碰用户的东西**）
  - 📈 自举链成长
- **元进化**：进化机制**本身**也能被审视优化。主触发=自主信号（用 `evolve-log health` 自查：机制连续无效 / 进化记录偏多 / 被纠正多 / 改得多却重复踩坑），命中即自主做机制体检+优化，不等收工。
- **蒸馏闭环**：讨论经验 → L2 Exp 踩坑 → 同主题 ≥3 条触发 → 蒸馏入 L3/index 结晶 → 提炼成 L2 Skill → 旧版进 L3/history。

## 十一、收工闭环与自省（Ritual.md）

**收工闭环（9 步）**——不是「聊完就散」，而是：更新 project.md → 更新待办 → 更新 L2 Skills → **蒸馏轮级缓冲**（先蒸馏后同步 Tree，让同步覆盖新落库）→ 更新 Tree.md → 清理 tasks → 汇报 → **机制体检（元进化）** → **收工自省（必走）**。

**行为问题尺（§五）**——这是它对自己第二序批判的产物：原「七美德×七原罪」是**品格名词（没刻度/名词而非行为/贴标签/病药混），当不了尺**。重构为 **7 条可答「是/否」的行为问题**，每条有判据 + 指向「下次改的动作」。例：

- 我是不是**没验证就给了确定结论/报「完成」**？
- 我是不是**为了让对方满意而放弃了真话**？
- 该**先搜/先召回/先看现有实现**的事，我跳过了吗？

> 自省纳入收工第 9 步——**必走，不靠「想起来」**。

## 十二、诚实看待：已知短板与设计张力

这套系统的自我评价（`心智系统评审报告_2026-09-04.md`，证据评审 ≈ **7.6/10 B+**）反而最能说明它的品质。真实缺陷与张力：

1. **实质数据深度 < 形式深度**（5 个可测信号 4 个为 0，117 条进化记录 0 次无效）——「机制比喂给它的证据多得多」。
2. **「自我治理」与「最低消耗/少而精」的内在冲突**：`AGENTS/TOOL/SOUL` 都喊省 token，但行为纪律细则有 14+ 条。系统用「常驻极简 + 按需读细则」调和（这是对的方向）。
3. 评审当时发现的**机制脱节**：`mind-validate`(c) 双版本校验曾是死代码、版本号四处漂移、检索逻辑双头实现。

> 好消息：这些在评审后有落地修复（见 `Project\DSHOME\project.md`）：2026-09-05/06 的「心智体系修复 v1」补齐 Tree↔_index 同步、AGENTS 双版本对齐、`mind-validate --strict` 全绿；B1/B3/B5 闭环（蒸馏链计数认领、首启自举、收工步序重排）；G 方案 II 护栏修正（避免「过了 validate 仍被拦」的双闸矛盾）。

## 十三、设计哲学总结（一句话）

> **口子上激进，骨子里克制。**
> 底板薄到只剩「防自欺」一根筋（记忆要么有源可溯、要么诚实标未验证；不搞厚重人审门禁），**因为防「错/失控/冗余」若做成硬墙，就把生长压死了**；但这根筋本身必须硬——判断层可以自由，**却永远不得违反确定性内核**。信任靠**溯源**挣来，不靠预设。
