## 6. 修订（2026-09-01 用户校准：之前做就十几分钟）

**结论**：上文的 12–16h 是「正规化工程包」口径（官方设置页 + host 文件存储 + 十条硬化 + 构建链未知），**不是功能本体**。用户以实操经验校准：核心功能十几分钟即可。

**快路径（客户端纯插件，全部可抄 DSHOME 现成模板）**：

| 项 | 做法 | 时间 |
|---|---|---|
| 注入器 + 名字 + 预设头像 | 抄 dshome-palette/plugin-center 的 ModuleLoader 骨架 + MutationObserver 注入 | **30 分钟–1 小时** |
| 本地上传（可选） | FileReader → 客户端压缩（~256px）→ **data URI 存 localStorage**（不需要 host 路由！） | +20–40 分钟 |
| 设置入口 | 会话头部按钮弹 vanilla 浮层（名字输入 + 预设网格），同插件中心风格 | 含在上 |
| 冒烟 | 默认关闭零回归 / 设置后所有会话生效 / 重启保留 / 幂等 | 10–20 分钟 |
| **合计** | 不含官方设置页、不含 host 文件存储、不做全套硬化 | **约 1–2 小时**（含上传） |

**与完整版的边界（诚实说明）**：
- **术语澄清**（用户问"官方设置页 / host 文件存储 / 十条硬化都是什么意思"）：
  - **官方设置页**＝把设置 UI 挂进官方设置面板（齿轮面板）成为其一节，需匹配官方 `settings.section` 的 React 组件契约；快路径用会话头部按钮弹自绘浮层，不需要它。
  - **host 文件存储**＝头像作为真实文件由后端（host）存盘并提供 HTTP 接口；快路径用 FileReader 压缩成 data URI 存 localStorage（浏览器侧，挂在固定 origin `127.0.0.1:3099` + Electron userData `%APPDATA%\dshome-shell`，重启保留、**换 DSH profile 不丢**；真正会丢的是清站点数据/删 userData/换端口/换机器）。
  - **十条硬化**＝设计文档 §9 我自己列的十条验收（文件类型/大小、XSS、流式幂等、明暗主题、重启持久化、零回归等）逐条核对——**这是我自加的验收仪式，不是用户要求的**。
- **框架纠错（2026-09-01 用户纠正）**：不存在「最小可用 vs 正规化」两级——快路径（客户端纯插件）就是**正确做法本身**，不是妥协版；上述三项是我臆想的外壳，不是"正式版"，也不该作为可选项推销。正确默认：按仓库自然方式实现；只有用户提出具体诉求（如"换 profile 不丢头像"）才引入对应机制。
