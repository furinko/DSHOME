# 插话功能：三档语义选型对比（2026-09-01）

> 状态：**选型文档（决策记录）**，仅评估与记录，未实施任何改动。
> 背景：用户希望在 agent「思考/工作」时可插话；已确认的方向是——能**选择直接插话还是预输入（排队）**，理想情况下**不打断思维链、而是把新消息注入下一步**。

---

## 1. 结论摘要

1. **「选择插话 / 排队」完全合理，且 DSH 核心已原生支持**（`busyEnter` 设置 + Enter / Ctrl+Enter 手势互为反向），不必自研基础通道。
2. **「不打断思维链、直接注入新消息」字面不可行**：LLM 一旦开始生成，提示词已固定，无法向正在生成的 token 流（含思维链）中途插入任何内容。**可行的近似是「下一步注入」**：当前生成自然跑完，新消息在下一个 step 边界注入 agent（`agent.steer()` 的落点）。
3. **市场已有现成插件覆盖三档**，建议「核心手势切换 + 市场插件三档可视化」组合，不必从零开发。

---

## 2. 三档语义定义

| 档位 | 触发 | 对当前回合的影响 | 用户感知 | 现有实现锚点 |
|---|---|---|---|---|
| **立即插话**（steer / now） | 忙碌中发送，选「立即」 | 掐断当前一次生成，安全收尾（已产出前缀保留、未派发的工具调用省略），agent 立刻处理新消息 | 最快响应；当前生成中断 | 核心 `prompt(mode:'steer')`、`dsh-interrupt-button` |
| **下一步注入**（next / steer-at-boundary） | 忙碌中发送，选「下一步」 | 当前生成**自然跑完不被掐断**；新消息在下一步边界注入 agent，agent 带着它继续决策 | 思维链完整；插话在下一步生效 | `agent.steer()`、`dsh-improved-inline-edit`、dsh-input-traffic 的 next |
| **排队**（queue / later） | 忙碌中发送，选「排队」 | 当前回合完整结束后按 FIFO 进入新回合 | 完全不打扰；有延迟 | 核心 `prompt(mode:'queue')`、`dsh-queue-plus` |

---

## 3. 关键机制约束（为什么「不打断思维链注入」做不到）

- LLM 流式生成是**一次性请求**：prompt 固定后，模型逐 token 输出，无法在输出中途改写输入；思维链（reasoning / CoT）同样受此约束。
- 真正可选的「插入点」只有两个：
  1. **掐断当前生成**（abort）：可做到，代价是丢弃未生成完的部分（`dsh-llm.interruptedBlocks()` 会保留已产出前缀，未派发的工具调用被省略）；
  2. **等当前生成结束**：不丢任何输出，新消息在下一个 step 边界注入（不打断进度，只是不打断不了「已开始的生成」）。
- 因此三档的本质是：**在「生成完成时刻」上选择**——立即掐断 / 等它跑完再注入 / 等整个回合跑完。

## 4. 对比矩阵

| 维度 | 立即插话 | 下一步注入 | 排队 |
|---|---|---|---|
| 响应速度 | 最快 | 中（等当前生成结束） | 最慢（等回合结束） |
| 思维链完整性 | 中断 | ✅ 完整 | ✅ 完整 |
| 任务进度保持 | 需 checkpoint 续接 | ✅ 无缝 | ✅ 无缝 |
| 上下文连贯 | 生成被截断，需重述 | ✅ 自然承接 | ✅ 自然承接 |
| 实现成本（自研） | 中（abort + 收尾） | 中（step 边界注入） | 低（已内置） |
| 核心现有支撑 | 有 | 有 | 有 |
| 市场插件支撑 | dsh-interrupt-button | dsh-improved-inline-edit / input-traffic next | dsh-queue-plus |

## 5. 现有支撑盘点（已实测/已核实）

### 5.1 DSH 核心（本机 node_modules/@deepseek-ai 源码确认）

- `dsh-client-runtime` 会话契约：`prompt(content, mode: 'queue' | 'steer')` —— steer 打断运行中的回合，queue 追加回合。
- `dsh-client-ui-conversation`：
  - `busyEnter` 设置（`queue` / `steer`，默认 queue）；
  - `ComposerSubmitGesture = 'enter' | 'accelerated'`，提交策略返回「首选模式或其相反」→ **普通 Enter 与 Ctrl/Cmd+Enter 互为反向选择**。
- `dsh-agent-loop` / `dsh-agent`：`agent.steer(message)` 投递到最近一步；inbox 分 queued / steering / context 三种落位；被拒绝的 steering 停在 inbox 等下次唤醒。
- `dsh-llm`：`interruptedBlocks()` 安全收尾被掐断的流。
- `dsh-session`：turn 带 `interrupted` 标记 + 崩溃恢复修补。

### 5.2 市场插件（dshmarket 目录，`/dsh-market/registry` 实测 2741 个插件）

| 插件 | 能力 | 对应档位 |
|---|---|---|
| dsh-improved-inline-edit | agent 工作时 composer 上方弹出输入框，`agent.steer()` 注入下一步，不停止对话；草稿按会话持久 | 下一步注入 |
| dsh-input-traffic | 三档（now/next/later）输入规划 dock，红/黄/绿优先级条，支持冻结/恢复 | 三档全覆盖（可视选择） |

## 6. 选型建议

**推荐组合**：
1. 核心 `busyEnter = steer`（默认手势=插话，Ctrl+Enter=排队），保证两档随时可用；
2. 装 **dsh-input-traffic** 提供 now / next / later 三档可视选择，直接满足「选择直接插话还是预输入」；
3. 若只想要「不打断的注入」，单装 **dsh-improved-inline-edit** 即可。

**不推荐自研起步**：核心已覆盖两档传输通道，缺的只是「每消息显式选档 + 三档可视化」，市场插件已补齐；自研收益低、风险高（client 插件构建链 + 版本族兼容）。

---

## 7. 验收标准（后续试装后按此核对）

1. 忙碌时发送消息，可选择档位（立即 / 下一步 / 排队）；
2. 插话消息在界面上有视觉区分（steering 气泡 / 优先级色条）；
3. 下一步注入：当前生成不被掐断，消息在下一步被 agent 看到并响应；
4. 排队：当前回合结束后按 FIFO 进入；
5. 立即插话：生成被安全收尾（前缀保留），agent 先回应插话，再继续或按指示转向原任务。

## 8. 风险与注意

- **版本族核对**（历史教训 DSHOME-ISSUE-001）：装社区插件前先 `npm view <pkg> peerDependencies --json`，rc↔rc / alpha↔alpha 对齐；装完重启后确认 web boot 无 `pending (waiting for service: xxx)`。
- **立即插话会截断生成**：已产出前缀保留（非全丢），但被截断内容不会自动补全。
- **「下一步」边界语义需实测**：`agent.steer()` 的投递窗口（哪些步骤算「下一步」）以实际行为为准。
- 若未来自研：改动面 = 前端 composer 显式选档 UI + 复用现有 `mode` 通道，**不动运行时核心**。
