# 对话区助手形象设定功能：设计文档（2026-09-01）

> 状态：**设计文档（决策记录）**，仅设计与评估，未实施任何改动。
> 范围：为 DSHOME 桌面客户端设计「设定对话区助手（AI）的头像和名字」功能。
> 已确认决策（2026-09-01 用户选定）：头像来源 = **本地图片上传 + 内置预设图标**；生效范围 = **全局统一**（所有会话同一形象）；**仅界面显示**，不写入系统提示词、不影响模型身份。
> **2026-09-01 实施口径修订（用户纠正）**：设置入口＝**官方「通用」设置内两行**（`settings.general.item` 加法槽），不做独立设置页；采用客户端纯插件快路径（localStorage 持久化 + DOM 注入器），**不再实施 host 路由与文件存储**。下文 §4–§8 中涉及 settings.section 独立页、host namespace/文件路由的章节仅作备选参考。

---

## 1. 结论摘要

1. **现状**：对话区助手消息（`assistant-step`）目前**只有 Markdown 正文，没有任何头像/名字 chrome**；用户消息是右侧气泡也无头像。整条消息被稳定地包在 `div[data-chat-flow-kind="assistant-step"]` 容器里（官方源码已核实）。
2. **可行且推荐的做法**：不改官方包源码，走 **DSHOME 自有 client 插件 + host 路由**（与 `dshome-theme` / `dshome-palette` / `dshome-plugin-center` 同一范式）：
   - **对话区注入**：一个轻量 DOM 注入器（MutationObserver + 稳定属性选择器），在每条助手消息容器顶部插入「头像 + 名字」行；幂等、流式重渲染免疫、升级免疫。
   - **设置入口**：注册官方设置面板的 `settings.section` 新页面「对话区形象」，改动即存。
   - **持久化**：host 侧注册 `dsh-settings` namespace `dshome.assistant-identity`（schema 校验、重启保留）+ 头像文件存 profile 数据目录，经 loopback `/api/dshome/*` 路由提供（复用现成 trust fence）。
3. **否决的路线**：重注册 `conversation.chat.node` 的 `assistant-step` 渲染器需要**自行重实现整套 Markdown/流式渲染链**（官方渲染器组件未从包导出），工程量与风险远大于收益，不采用。
4. **默认关闭**：未设置任何形象时，对话区与现状完全一致（零回归）。

## 2. 需求与已确认决策

| 问题 | 决策 | 影响 |
|---|---|---|
| 头像来源 | 本地图片上传 + 内置预设图标（不做 URL、不做首字母自动生成） | 需要文件存储与上传通道；预设可全内置 |
| 生效范围 | 全局统一（所有会话同一形象） | 单份配置，无会话级状态 |
| 是否影响模型 | 仅界面显示，不写系统提示词 | 不动 `dsh-persona` / 提示词注册表 |
| 默认行为 | 未配置时完全隐藏 chrome | 保证零回归 |
| 名字规则 | 空=不显示名字；≤24 字符 | 设置页输入框约束 |

隐含需求（设计自定，可被用户纠正）：
- 设置入口放在**官方「通用」设置面板**内新增**两行**（名字行 + 头像行，走 `settings.general.item` 加法槽），不做独立设置页，也不在会话头部加按钮。
- 头像/名字属于**每条助手消息**（每个 `assistant-step` 行），而非每回合只显示一次；这是聊天应用惯例。

## 3. 现状盘点（已核实，2026-09-01 源码确认）

### 3.1 对话区渲染
- `@deepseek-ai/dsh-client-ui-conversation`（bundle：`node_modules/@deepseek-ai/dsh-client-ui-conversation/lib/client.js`）：
  - `AssistantNodeView`（约 L9526）只渲染 `AssistantMarkdown`（blocks + 流式/中断状态），**无头像、无名字**。
  - 渲染器注册在槽 `conversation.chat.node`，`key: "assistant-step"`（L9776-9780）。
  - `ChatNodeSeat`（L5506-5510）把每条消息包进 `div.Md3f7G_flowItem`，恒定输出 `data-chat-flow-kind={node.kind}`（助手消息即 `assistant-step`）、`data-chat-anchor-key` / `data-chat-flow-key`。→ **这是稳定的注入锚点**。
- 用户消息：`UserMessageNodeView`（L5384+），右侧气泡（`userRow`/`bubble`），无头像。
- 官方渲染器组件**不导出**：bundle 以 `window.__ModuleLoader__.load({ id, factory })` 自注册，`require('@deepseek-ai/dsh-client-ui-conversation')` 得到的是插件对象而非组件 → 第三方无法复用 `AssistantMarkdown`。

### 3.2 槽体系（可扩展点，官方契约明说「加设置永远不用改 shell」）
- `settings.section`（list，root 作用域）：注册一个设置页面。官方范式见 `dsh-client-ui-settings-general`（L585-595，`id: "general"`）；DSHOME 自有注册范式见 `dshome-plugin-center`（`ctx.slots.inject(...) => ctx.slots.register({ name, id, order, label }, Component)`）。
- 品牌槽 `sidebar.brand.mark` / `sidebar.brand.name` / `conversation.hero.brand.mark`：DSHOME 已通过 `dshome-theme` 注册（可复用其「嵌套 inject + 生成器 yield」注册技巧与 React 组件写法）。

### 3.3 DSHOME 自有插件范式（可直接照抄的样例）
- Client 插件：`window.__ModuleLoader__.load({ id, factory: (require) => {...} })`，导出 `{ name, inject, apply }`；React 组件用 `require("react/jsx-runtime")`、`require("@deepseek-ai/dsh-client-ui-primitives")`。样例：`packages/dshome-theme/lib/client.js`、`packages/dshome-plugin-center/lib/client.js`。
- 插件名录：`packages/dshome/package.json` → `dsh.client.inject: ["dshome-theme", "dshome-palette", "dshome-plugin-center"]`。
- Host 路由：`packages/dshome/lib/host/plugin-api.js` 给出完整范式——`isTrustedLocalRequest`（loopback trust fence）+ `webServer.register({ kind: "exact", path, handler })`，经 `inject: ["webServer"]` 的子插件激活；`/api/dshome/plugins` 即此实现。
- 持久化：`@deepseek-ai/dsh-settings` 支持 `ctx.settings.register(namespace, schema)`（schemastery schema、revision 安全写、序列化写链、重启保留）。

### 3.4 生效前提（实施时实测，勿想当然）
- DSHOME client 插件如何进入运行中的 GUI，本检出（`E:\DSHOME`，无 `apps/web` 源树）未直接可见：市场插件（`dsh-input-traffic`）有「client bundle 逐请求读盘、改文件刷新页面即生效」的实测先例，但 DSHOME 自有 workspace 插件是否同一机制**需实施时先验证**（改一行注释 → 刷新 → 看是否生效）。
- 历史教训：发版/构建链相关改动必须验证**运行中界面**，不能只看文件存在；若需重建产物，按实际可用的构建入口执行并在验收时记录。

## 4. 总体架构

```
┌─────────────────────────── 浏览器侧（client 插件 dshome-assistant-identity） ───────────────────────────┐
│                                                                                                          │
│  ① 通用设置两行（settings.general.item：名字行 + 头像行）                                                            │
│     · 名字行：标签 + 单行输入（≤24 字符，空=不显示）                                                                │
│     · 头像行：当前头像预览 + 预设网格选择 + 本地上传（FileReader → data URI）                                      │
│     · 两行改动 → 写 localStorage（key: dshome.assistant.identity）→ dispatch 变更事件                               │
│                                                                                                          │
│  ② 对话区注入器（apply 时启动，常驻）                                                                     │
│     · 启动时 GET /api/dshome/assistant-identity 取配置缓存                                                 │
│     · MutationObserver(document.body, subtree+childList)：                                                │
│        新增 div[data-chat-flow-kind="assistant-step"] 且无 data-dshome-identity →                         │
│        在其顶部插入 <div class="dshome-identity">（头像 img + 名字 span）                                  │
│     · 收到变更事件 → 更新缓存 → 删除全部已注入节点 → 对现存行重灌                                         │
│     · 名字用 textContent 注入；图片加载失败 onerror → 只留名字/隐藏头像                                    │
└──────────────────────────────────────────────────────────────────────────────────────────────────────────┘
                                    │ fetch（loopback，同源）
                                    ▼
┌─────────────────────────── 宿主侧（host 插件）【快路径不实施，仅备选参考】────────────────────────────┐
│  （若要"跨机器/清站点数据也不丢"才需要：/api/dshome/assistant-identity 路由 + 头像文件存储 +           │
│    dsh-settings namespace dshome.assistant-identity；实现范式见 §8 与 plugin-api.js）                     │
└──────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

数据流（快路径）：通用设置两行保存 → 写 `localStorage` → 注入器缓存刷新 → 所有会话的助手消息即时换肤。全程**在浏览器侧完成**，不经过模型侧，也无 host 参与。

## 5. 数据与存储设计

### 5.1 settings namespace（schemastery schema）

```ts
// namespace: 'dshome.assistant-identity'（小写 kebab，满足 dsh-settings NAMESPACE_PATTERN）
{
  name:   z.string().max(24).default(''),            // 空 = 不显示名字
  avatar: z.union([
    z.object({ kind: z.literal('none') }),            // 不显示头像（默认）
    z.object({ kind: z.literal('preset'), preset: z.string() }),  // 内置预设 id
    z.object({ kind: z.literal('file'),  file:  z.string() }),    // 上传文件 uuid
  ]).default({ kind: 'none' }),
}
```

显示规则（三者组合）：
| name | avatar | 对话区效果 |
|---|---|---|
| 空 | none | **不注入任何 chrome**（功能关闭态，零回归） |
| 有 | none | 只显示名字 |
| 空 | preset/file | 只显示头像 |
| 有 | preset/file | 头像 + 名字 |

### 5.2 内置预设头像（8 个，全部客户端内置，零网络）

`fish`（官方鲸鱼，可复用 `dsh-client-ui-primitives.FishLogo` 或导出 SVG）、`robot`、`star`、`moon`、`cat`、`bolt`、`paw`、`gem`。以 SVG data URI 内嵌在 client 插件中（明暗主题下用固定色或 `currentColor` 自适应）。

### 5.3 上传文件

| 项 | 约束 |
|---|---|
| 类型白名单 | `image/png`、`image/jpeg`、`image/webp` |
| 大小上限 | 2 MB |
| 存储位置 | `<profile数据目录>/dshome/avatars/<uuid>.<ext>`（uuid 由 host 生成，避免路径注入/覆盖） |
| 引用方式 | settings 只存 uuid；GET 路径 `/api/dshome/assistant-avatar/<uuid>` |
| 缓存 | GET 响应带长缓存头 + 文件名变化即换 URL（uuid 天然防陈旧） |
| 清理 | 替换头像时删除旧文件；提供「清除头像」动作 |

### 5.4 API 一览（全部 loopback fence + JSON/no-store）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/dshome/assistant-identity` | 返回 `{ ok, identity: { name, avatar } }` |
| PUT | `/api/dshome/assistant-identity` | body `{ name, avatar }`，校验后 `settings.patch`，返回 `{ ok }` |
| POST | `/api/dshome/assistant-avatar` | body（JSON/base64）`{ data, ext }`，落盘并返回 `{ ok, file: uuid }`；越界返回 400 |
| GET | `/api/dshome/assistant-avatar/<uuid>` | 图片字节（content-type 按 ext，长缓存） |
| DELETE | `/api/dshome/assistant-avatar/<uuid>` | 删除文件 + 清除引用，返回 `{ ok }` |

## 6. 对话区注入设计（核心，方案选型）

### 6.1 方案对比

| 方案 | 做法 | 结论 |
|---|---|---|
| **A. DOM 注入器（采用）** | MutationObserver 监听 `div[data-chat-flow-kind="assistant-step"]`，行首插入 `.dshome-identity`（头像+名字），`data-dshome-identity` 幂等 | ✅ 不依赖官方渲染器内部；流式重渲染由观察器自动补灌；与 dshome-palette/plugin-center 的 vanilla 风格一致；升级免疫（锚点是官方稳定属性） |
| B. 重注册 assistant-step 渲染器 | 在 `conversation.chat.node` 用 key=`assistant-step` 覆盖注册自定义组件 | ❌ 官方 `AssistantMarkdown` 不导出，需自实现 blocks/流式/中断/工具引用/图片渲染全链，风险大收益低 |
| C. 纯 CSS ::before | 用 `content: attr(data-*)` + `background-image` 渲染名字/头像 | ⚠️ 头像需 background-image（预设 data URI 可行，上传文件需 URL），布局受伪元素限制（flex 行/间距难控），仅作备选 |

### 6.2 注入结构

```html
<!-- 目标行（官方 ChatNodeSeat 恒定输出，不改动） -->
<div data-chat-flow-kind="assistant-step" data-chat-anchor-key="...">
  <!-- 注入（幂等标记 data-dshome-identity="1"） -->
  <div class="dshome-identity" data-dshome-identity="1">
    <span class="dshome-identity-avatar"><img src="..." alt="" /></span>
    <span class="dshome-identity-name">我的助手名</span>
  </div>
  <!-- 官方原有内容（AssistantMarkdown 等）不动 -->
  ...
</div>
```

样式（全部走设计 token，明暗自适应）：
```css
.dshome-identity{display:flex;align-items:center;gap:8px;margin:0 0 6px 2px}
.dshome-identity-avatar{width:28px;height:28px;border-radius:50%;overflow:hidden;flex:none;
  background:var(--dsw-alias-interactive-bg-hover);display:inline-flex;align-items:center;justify-content:center}
.dshome-identity-avatar img{width:100%;height:100%;object-fit:cover;display:block}
.dshome-identity-name{font-size:13px;font-weight:600;color:var(--dsw-alias-label-secondary);
  max-width:min(60vw,480px);overflow:hidden;text-overflow:ellipsis;white-space:nowrap}
```

### 6.3 关键实现要点

- **幂等**：以行元素上 `data-dshome-identity` 属性为准，重复回调直接跳过；React 重渲染若保留同一 DOM 节点则不动，若替换节点则观察器补注入。
- **性能**：observer 只对 `addedNodes` 里含该属性的元素做一次 `closest()` 检查；聊天区行数级观察开销可忽略。
- **配置变更**：注入器缓存当前 identity；设置页保存后 dispatch `dshome:assistant-identity-changed`，注入器清空重灌（对现存行与未来行一致）。
- **图片失败兜底**：`img.onerror` → 隐藏头像元素（只留名字）；上传文件被删/损坏时不出现裂图。
- **多会话/翻页/压缩（compaction）**：行被卸载重建是常态，观察器覆盖即可，无额外状态。

## 7. 设置 UI 设计（官方「通用」设置内两行）

- 注册：`settings.general.item` **两行**（官方契约：list 槽、行自带标签/当前值/写路径，"加设置永远不用改 shell"；ui-settings-general 的 General 条目已在运行时声明该 seat）：
  - **行1**（`id: "dshome-assistant-identity-name"`）：标签「助手名字」+ 单行输入框（`maxlength=24`，空=不显示）；
  - **行2**（`id: "dshome-assistant-identity-avatar"`）：标签「助手头像」+ 当前头像小预览 + 预设网格（8 个 +「无」）+「上传本地图片」（隐藏 file input，`accept="image/png,image/jpeg,image/webp"`）。
- 两行共用配置，存 `localStorage` key `dshome.assistant.identity`（`{ name, avatarKind: 'none'|'preset'|'file', avatarPreset?, avatarDataUri? }`）；改动即写 + dispatch `dshome:assistant-identity-changed` 供注入器刷新。
- 行内效果预览：每行下方小字模拟「头像 + 名字」当前效果（设置面板与对话区不同屏，行内预览所见即所得）。
- 上传处理：FileReader 读图 → 客户端压缩（~256px，`canvas.toDataURL('image/webp')` 或 jpeg）→ data URI 存 localStorage（512KB 级足够）；类型/大小越界（>2MB）直接提示拒绝。
- 错误处理：文件类型/大小越界提示；名字为空即不显示名字（合法态）。

## 8. 实现步骤（实施口径＝客户端纯插件快路径）

1. **client 侧（唯一实施项）**：新增包 `packages/dshome-assistant-identity/`
   - `lib/client.js`：`window.__ModuleLoader__.load` 范式；导出 `{ name, inject: ["slots"], apply }`；
   - apply 内：注入样式（§6.2 CSS）→ 启动注入器（§6.3）→ 注册 `settings.general.item` 两行（§7）；
   - 配置读写：localStorage（key `dshome.assistant.identity`）+ 变更事件；包内内置 8 个预设 SVG（data URI）；
   - 上传：FileReader → 客户端压缩（~256px）→ data URI 存 localStorage。
2. **接入名录**：`packages/dshome/package.json` → `dsh.client.inject` 追加 `"dshome-assistant-identity"`；`dependencies` 加 `"dshome-assistant-identity": "workspace:*"`。新包必须裸跑后端冒烟确认可加载（ISSUE-001 教训：只验证"包可解析"不够，要验证"可加载"；无 host 行为的入口照抄 `dshome-palette/lib/index.cjs` 的 `{ name, apply() {} }`）。
3. **验证**：先实测 client 插件生效方式（改注释→刷新页面看是否热生效，见 §3.4）；冒烟覆盖 §9 关键项（零回归 / 显示 / 重启持久 / 幂等 / 明暗主题）。
4. **备选（仅当用户提出"跨机器 / 清站点数据也不丢"等具体诉求时才实施）**：host 侧 `packages/dshome/lib/host/assistant-identity.js`（settings namespace + 头像文件路由，范式见 §3.3 / plugin-api.js）。注：localStorage 挂在固定 origin `127.0.0.1:3099` + Electron userData（`%APPDATA%\dshome-shell`），**换 DSH profile 不会丢**（profile 不影响该存储）。

## 9. 验收标准

1. 未设置任何形象时，对话区与现状完全一致（无头像/名字，无注入节点残留）——**零回归**。
2. 设置名字后，所有会话的每条助手消息上方出现该名字（左对齐、次级色、≤24 字符截断），流式输出过程中稳定显示。
3. 选择预设头像后，消息显示圆形预设头像；上传本地图片后显示上传图，上传后**即时预览**、**重启后仍存在**。
4. 清除头像 / 清空名字后，对应 chrome 即时消失；全部清除回到关闭态。
5. 设置入口：官方设置面板左侧导航出现「对话区形象」页面，改动即存（无保存按钮依赖）。
6. 明暗主题下头像/名字均清晰可读（token 驱动）。
7. 流式重渲染 / 翻页 / 压缩后不重复注入（`data-dshome-identity` 幂等）、不闪烁错位。
8. 越界上传（>2MB / 非白名单类型）被拒绝并提示；名字注入全程 `textContent`，无 XSS 面。
9. 系统提示词与模型行为不变（仅界面显示）。
10. 修改 client 插件后经重建/刷新在运行中 GUI 生效（发版前冒烟）。

## 10. 风险与注意

- **构建链依赖**：client 插件改动能否「改文件即生效」需实施时实测（§3.4）；若需重建，按实际入口执行并验证运行中 GUI；发版时同步版本号（`DSHOME_VERSION` 曾漏更的历史教训）。
- **官方升级兼容**：注入锚点 `data-chat-flow-kind` 与 `settings.section` 槽均为官方契约；若未来官方给消息行加自己的头像/名字 chrome，需评估去重（观察器仍幂等，视觉上可能并存，届时再议）。
- **MutationObserver 开销**：仅观察新增节点 + 属性短路检查，量级可接受；若未来出现卡顿，可收窄观察范围为 `[data-conversation-scroll]` 容器。
- **头像文件生命周期**：uuid 命名防覆盖；替换清理旧文件；`<profile数据目录>/dshome/` 目录随 profile 保留、升级包不覆盖。
- **loopback fence**：所有 `/api/dshome/assistant-*` 必须过 `isTrustedLocalRequest`，防止跨站读取本地头像（隐私）。
- **不做的范围**（防蔓延）：不改官方包源码；不重实现 Markdown 渲染器；不做 URL 头像；不做每会话覆盖；不写系统提示词。
