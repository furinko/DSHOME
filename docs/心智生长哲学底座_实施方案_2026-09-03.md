# 心智生长哲学底座 · 实施方案

> 状态：**提案（待实施）** | 2026-09-03 | 目标机器：**干净的 DSHOME（仅 `mind\` 出厂固件，无 `mind-private` 记忆/项目）**
> 目的：把「防自欺」（别让心智对自己撒谎）从**哲学/规则**落成**机制**——让它真的会被执行，而不是只写在文档里。

---

## 0. 一句话目标

把下面这条「筋」变成机器会去执行的机制，而不是只写进规则：

> **记忆要么有源可溯（外部可查证依据），要么诚实标 `unverified`（不参与权威）。别让无根据的东西冒充权威。**

---

## 1. 现状与缺口

| 层 | 状态 | 内容 |
|---|---|---|
| 哲学/规则层 | ✅ 已落 | `mind\L1\Design-Philosophy.md`（生长哲学+性格罗盘）· `mind\L1\Memory.md` §八（溯源信任）· `mind\L1\Invariants.md` #6 · `mind\L1\Concepts.md`（权威源路由） |
| **机制/代码层** | ❌ **未落** | 见下四条缺口 |

**缺口（本次要补的机制）：**
1. 记忆 `source` / `verified` 字段**没进 schema**——现有记忆文件均无此字段；`mind-validate` §② 只查 `kind/importance/scope/topic/tags`，**不查 source/verified**。所以"无源标 unverified"目前只是规则，没被强制。
2. **主会话开机硬注入 hook**（host/preset 层）——未做；`mind-prime` 仅在 `cron.cjs`（定时任务）被调用，主会话靠 AGENTS 指令，无硬 hook。
3. **离线漏查审计**（"该查没查"）——未做。
4. **撞名消歧**（歧义词先钉身份）——仅为哲学原则，未成机制。

## 2. 组件与落点

### 组件 A：记忆 schema 强制溯源/降权（低风险，先做）
- **目标**：写记忆时，要么 `source`（外部可查证依据），要么 `verified: false`（降权）。
- **改动**：
  - `scripts\mind-validate.mjs` §②：L3 记忆校验扩展——`source` 或 `verified:false` **至少其一**（有 source → OK；无 source 且无 `verified:false` → critical）。
  - `mind\L1\Memory.md` §八：把 source/verified 字段规则写进记忆 frontmatter 约定（`source` = 外部可查证依据：文件/事件/用户明示/实测；agent 自推理不算 source）。
- **边界**：现有存量记忆（无 source/verified）→ 视为"未验证"，迁移时补标或接受提示。
- **验证**：`node scripts/mind-validate.mjs` 通过。

### 组件 B：主会话开机硬注入（中风险，动宿主）
- **目标**：每次主会话开始**结构性**装配 `mind-prime` 产物，不靠 agent 记得跑。
- **落点**：`@deepseek-ai/dsh-agent-instructions`（AGENTS.md 工作区指令注入）或 preset 层加**会话起始 hook**，把 `mind-prime` 输出确定性塞进首发系统上下文。
- **参考**：`packages\dshome-mind\lib\cron.cjs` 已用 `execFileSync(process.execPath, [scripts/mind-prime.mjs])` 前置到任务 prompt——主会话复用同一装配器即可。
- **注意**：**无记忆环境优雅降级**——`mind-prime` 在无 `mind-private` 时输出空/不炸（`search()` 空库返回空 hit；`project()` 无档返回空）。
- **验证**：新会话首轮上下文出现"【上工自动召回】"块。

### 组件 C：离线漏查审计（低优先级，观测器）
- **目标**：批量审计"该查没查"，≥3 次晋升成"意图→记忆弱路由"建议（用数据长，不拍脑袋）。
- **落点**：新建 `scripts\mind-audit.mjs`（或并入 cron/curate 通道），离线跑；不拦 commit，只产出候选。
- **验证**：跑一遍出"该查没查"候选列表。

### 组件 D：撞名消歧（机制）
- **目标**：歧义词（如 `DSHOME` 同时指"产品/仓库"与"心智项目"）先钉身份再动手，不裸词乱搜。
- **落点**：召回/装配前，一个词命中多个候选对象时返回候选并提示"指哪个"；规则登记到 `mind\L1\Concepts.md` 或单独消歧清单。
- **验证**：搜"DSHOME"返回多候选并提示消歧。

---

## 3. 实施顺序（去风险）

1. **A（schema + validate）**——只动出厂 schema/校验，最稳，先落。可在无记忆的干净机器上做。
2. **B（开机注入 hook）**——动宿主，次之；需在真实 DSHOME 上建会话实测。
3. **C、D**——观测/消歧，后落（靠数据/实际场景驱动，不预先定死）。

> 每步独立可验证、可回滚（改前 `evolve-log snapshot` + 改后 `mind-validate`）。

---

## 4. 验证门（每步）

- `node scripts/mind-validate.mjs` → critical=0。
- **无记忆环境**：`mind-prime` / `/api/mind/search` / schema 校验在空库下 graceful（不抛错、输出空、不炸）。

---

## 5. 边界 / 注意（重要）

- 🔴 **家里机器无 `mind-private`**：记忆/项目/Learn 全在本机、**gitignore 永不推送**。所以底座机制必须**落在出厂层**（`mind\` + scripts + packages，随仓库推送）；家里拿到的是"只有出厂固件、零私有记忆"的干净 DSHOME。
- **source 必须是外部可查证依据**（文件/事件/用户明示/实测），agent 自推理**不算** source → 标 `verified: false`。
- **别把它做成厚重门禁**（违背底座薄）：只补 source/unverified 校验 + 开机注入 + 观测器，**不加人审门槛**（pending 仅可选审阅，非强制）。
- 本轮**只推送出厂层 + 本文档**；`mind-private`（记忆/项目/Learn/快照/进化档案）不推。
