## 0. 一句话目标

把下面这条「筋」变成机器会去执行的机制，而不是只写进规则：

> **记忆要么有源可溯（外部可查证依据），要么诚实标 `unverified`（不参与权威）。别让无根据的东西冒充权威。**

## 2. 组件与落点

### 组件 A：记忆 schema 强制溯源/降权（低风险，先做）— ✅ 已落地
- **目标**：写记忆时，要么 `source`（外部可查证依据），要么 `verified: false`（降权）。
- **改动（已实施）**：
  - `scripts\mind-validate.mjs` §②：L3 记忆校验扩展——`source` 或 `verified:false` **至少其一**（有 source → OK；无 source 且无 `verified:false` → critical）。同脚本顺带修复两个前置 bug：① frontmatter 解析 LF-only 正则对 CRLF 文件误报「缺 frontmatter」（5 个 Skill 假阳性）→ 解析前归一化换行；② `related: [a, b]` YAML 数组未剥方括号即拆逗号 → 误报死链。
  - `mind\L1\Memory.md` §八：补「溯源契约」段——frontmatter 必须带 `source` **或** `verified: false`；`source` = 外部可查证依据（文件/事件/用户明示/实测），agent 自推理不算；存量记忆迁移时补标，校验不过阻塞提交。
  - 存量迁移：`mind-private\L3\index\游戏数值\` 4 条旧记忆（`> date:` 引用式头、无 frontmatter）→ 全部补标准 frontmatter（kind/importance/scope/topic/tags/source/related 精确文件名），正文保留，原元数据行并入 frontmatter 并留迁移注记。
- **验证**：`node scripts/mind-validate.mjs` → critical=0 warn=0（落地前 9 critical）。✅

### 组件 B：主会话开机硬注入（中风险，动宿主）— ✅ 已落地并经真实 DSHOME 会话实测
- **目标**：每次主会话开始**结构性**装配 `mind-prime` 产物，不靠 agent 记得跑。
- **落点（已实施）**：`packages\dshome-mind\lib\index.cjs`（出厂宿主插件，junction 到 profile，随仓库推送）——`apply(ctx)` 注册 `ctx.on('agent/pre-step')`（官方 dsh-agent-instructions / dsh-plan-mode 同款机制）：每 agent 运行实例只尝试一次，把 `mind-prime` 文本产物作为 user 上下文消息插入（**对齐官方：插到 claimed 用户消息之后、系统上下文之前**，非简单尾部追加）；只注入**顶层会话**（`delegationDepth>0` 的子代理跳过，避免重复 exec/上下文噪音）；已含【上工自动召回】（如 cron 前置）→ 跳过防双份；脚本失败/空库/无正文 → 不注入不阻塞，优雅降级。
- **机制置信度**：cordis 事件模型中插件 root ctx 的 `ctx.on` 与 agent loop 共享 hook 表，agent carrier 的 scope filter 对无 scope tag 的 root hook 放行（`tag === void 0 → return true`）——官方 goal-round-driver / dsh-agent-instructions 即以此收到 agent 事件（本会话 goal 机制能跑即证据）。
- **观测通道（新增）**：hook 每尝试一个 agent 都会记录到模块级 `bootRecallState`（registered / agents 计数 / 每 agent state / lastInject），并由 `/api/mind/status` 的 `bootRecall` 字段暴露——无需翻日志即可确认 hook 是否注册、是否触发、是否成功注入。
- **验证（全部通过）**：
  - 语法 `node --check` ✅
  - **cordis 运行时集成测试 `node scripts\mind-boot-recall-itest.mjs` 5 场景全绿** ✅——真实 cordis ctx 加载 dshome-mind 插件、模拟 agent/pre-step：① 顶层 agent 首步注入【上工自动召回】（真实 exec mind-prime）② 同 agent 二次幂等 ③ 子代理（delegationDepth>0）跳过 ④ cron 已含召回防双份 ⑤ 注入位置在 claimed 之后。
  - **真实 DSHOME 实测（宿主重启后，2026-09-03 23:48）** ✅——新会话首轮上下文出现「【上工自动召回 · DSHOME 心智】」块；`/api/mind/status` → `bootRecall.registered=true`、`lastInject.agentId=session-0ca1…`（该新会话）、`hookError` 空；`node scripts\verify-boot-recall.mjs` exit 0 ✅「hook 已注册 —— 组件B 已生效」。宿主 pid 33640（重启后）加载 junction 指向的最新 packages 代码。
- **注意**：**无记忆环境优雅降级**——`mind-prime` 在无 `mind-private` 时输出空/不炸（`search()` 空库返回空 hit；`project()` 无档返回空；hook 判无正文即不注入）。

### 组件 C：离线漏查审计（低优先级，观测器）— ✅ 已落地

## 5. 边界 / 注意（重要）

- 🔴 **家里机器无 `mind-private`**：记忆/项目/Learn 全在本机、**gitignore 永不推送**。所以底座机制必须**落在出厂层**（`mind\` + scripts + packages，随仓库推送）；家里拿到的是"只有出厂固件、零私有记忆"的干净 DSHOME。

- **别把它做成厚重门禁**（违背底座薄）：只补 source/unverified 校验 + 开机注入 + 观测器，**不加人审门槛**（pending 仅可选审阅，非强制）。
